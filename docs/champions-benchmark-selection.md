# Champions 实验结论与 benchmark 选例

## 本轮目标与已取得的证据

本轮目标是寻找有代表性的 test case，构建后续优化用的 benchmark。当前已完成输入快照、全量筛查和结果归档；后续从两个方向推进：让正常返回的未收敛项收敛，以及让无法返回结果的项恢复有预算约束的正常返回。

实验见 [2026-09-07 报告](optimization-records/champions-2026-09-07.md)及[原始 JSONL](optimization-records/champions-2026-09-07.jsonl)，配置与移植限制见[输入说明](champions-benchmark.md)。前十共 405 个血量配对：54 可测，16 达标、29 正常返回但未收敛、9 watchdog；另外 351 因源数据缺失或 Mega 行动不支持而跳过。

历史口径固定为 Node v24.20.0、@pkmn/sim 0.10.11、同步 backend、workers=0、无预热、每例一个新进程和一个正式样本、原生最大 PP。搜索预算 10 秒，容差 0.02，30 秒进程 watchdog；prepare/search/total 分别记录。当前数据是一次筛查，不是各 case 耗时的稳定分布，也没有证明任何具体机制就是瓶颈。

## 扩展项与边界检查

- `garchomp-100-vs-archaludon-100`：W1 恢复返回后的满血压力项。同配对其余七种血量也应回归，避免只改善低血量早结束路径。
- `archaludon-100-vs-mimikyu-25`：搜索约 10.002 秒后区间仍为 `[-1, 1]`。作为 U3 的同配对扩展，检查“搜索执行了，但根区间没有缩小”的表现；这不等于内部没有进展，也不能据此认定算法停滞。
- `primarina-25-vs-mimikyu-50`：数值边界项。原始宽度为 `0.020000000054120726`，比 0.02 大约 `5.4×10⁻¹¹`；当前收敛比较允许的额外量为 `1e-12`，所以结果标记未收敛并不与打印成 `0.020` 矛盾。应单独审计区间外扩、浮点保护和收敛比较，不能通过放宽容差或删除安全余量冒充性能收益。实际 search 也为 10.039 秒，改变收敛标签本身不代表严格 10 秒达标。

因此，之前对“未收敛主要来自未证明分支”的解释需要保留这项例外：本次确实有一个紧贴数值阈值的样本，不应把全部未收敛项都视作大规模搜索不足。

## 两条优化方向的验收指标

### 正常返回但未收敛

保持输入、原生 PP、容差和 backend 不变，记录：是否在实际 search≤10 秒时收敛、预算结束时的安全区间及宽度、prepare/search/total、展开状态数、转移数、模拟器重放次数，以及内存峰值（本次尚未采集）。

最终目标是安全区间宽度≤0.02 且实际 search≤10 秒。中途可以用同预算下的区间收窄衡量进展，但不能把“更窄”算作已经达标；不能用区间宽度比推算需要几倍提速。历史区间之间的包含或相交只是辅助检查，不代替价值证书正确性验证。

### watchdog：首先恢复有证书的正常返回

首先需要观测 prepare、转移、backup 等阶段的开始与结束，记录正在执行的行动组合、重放/分支数量、当前可用的安全区间和内存；现有 watchdog 行没有这些信息，不能断言一定卡在转移、一定是 Scale Shot × Stamina，或一定是内存问题。这些机制可以成为待验证假设。

区分两个里程碑：

1. **恢复返回**：搜索能按预算结束，交还有效安全区间；允许尚未收敛。若中断部分展开，未完成分支仍必须保留未知界，不能丢弃概率质量或当作已知价值。
2. **求解达标**：在上述基础上，实际 search≤10 秒且达到 0.02 容差。

仅仅把外部 watchdog 从 30 秒改为 10 秒、让进程更早被杀，不算恢复返回；把 watchdog 改成返回一个无依据的数值也不算。预算检查的超时幅度应独立报告。

## 复测与范围

已有入口可以按完整 ID 单独测量，无须修改配置：

```bash
npm run build
node dist/src/champions-benchmark.js primarina-100-vs-archaludon-25
node dist/src/champions-benchmark.js garchomp-25-vs-archaludon-25
```

每次单例命令会覆盖根目录的 `champions-single.jsonl`；在下一次运行前把文件保存到对应实验目录。要运行其他入选项，使用上表完整 ID。原始历史 JSONL 保持不变；以后每轮记录自己的版本、命令、环境、PP、workers、预热与样本数、backend 和分项耗时。

当前六项是建议固定的日常集合；正式优化前先重复复现目标与对照，建议至少 3 个新进程样本，保持无预热口径。若另测常驻 pool 或目标路径预热，应与当前冷进程基线分开比较。性能测量和功能测试分开运行，优化阶段结束后回归全部 54 个可测 case；被跳过的 351 个不能算作性能成功。

该选例阶段只完成实验记录与 benchmark 选例，没有扩展 Mega 行动、补缺失网站数据或修改求解器。未来优化优先基于通用状态、概率和数值证书；当前实例仍依赖 1v1 的行动生成和有限 PP 假设，对完整单打、换人或双打的可推广性尚未验证。

## 后续可扩展性优化结果

[2026-09-07 优化验收](optimization-records/champions-scalability-2026-09-07.md)完成了本集合的三次复测与全量回归：U2 三次在 10 秒内收敛，W1 三次约 70 ms 收敛；全量达标数从 16 增至 24，九项 watchdog 全部恢复返回，原达标项无退化。U1、U3、P2 满血的陆鲨／铝钢桥龙组合及数值边界项仍未达标；保留已解决项作为回归对照。上面的原始选例表保持为当时证据，最新分项计时及区间以该验收记录为准。

随后[策略证书搜索验收](optimization-records/strategy-certificates-2026-09-07.md)将达标数提高到 29/54，原 24 项无退化。满血陆鲨／铝钢桥龙三次 search 为 7.82–8.05 秒，发现地震策略后，其余 12 个根矩阵格保持未知即可完成 0.02 证书；建议保留为策略发现回归项。新增成功还包括西狮海壬 25% 对谜拟丘三档 HP，以及西狮海壬 50% 对谜拟丘 25%。数值边界项因此在未放宽容差的条件下完成收敛；其余 25 项继续作为优化池，完整失败列表见[本轮全量筛查](optimization-records/strategy-certificates-sweep-2026-09-07.md)。
