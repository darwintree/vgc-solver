# 优化技术

这里回答：当前采用的方法为什么有效、为什么正确、在哪些条件下能推广。以方法论与具体推演为主，代码路径与测试作为文末索引。实验过程与历史成绩见[优化记录](../optimization-records/README.md)。

## 从成本来源选择方法

| 要减少的工作 | 已采用的方法 | 阅读 |
| --- | --- | --- |
| 重复枚举同一种随机结果 | 就地分叉、等价随机桶、伤害饱和与终局聚合 | [随机结果等价合并](random-outcomes.md) |
| 查询或排序不会影响结果的事件 | 保守事件集合、空分发消除、独立计时状态的排序合并 | [事件工作消除](event-work.md) |
| 为等价状态重做恢复、计算或转移 | 隔离快照、相对状态键、带适用区间的 PP 模板与二次请求准入 | [状态与转移复用](state-reuse.md) |
| 精确求解并不需要的后继计算 | 延迟递归、极值／鞍点证书、矩阵数值证书 | [精确价值证明](exact-certificates.md) |
| 为误差目标之外的信息做搜索 | 上下界传播、逐格策略证明、按证明类型调度、增量更新 | [有界搜索](bounded-search.md) |
| 可独立完成的转移串行等待 | 常驻 worker、批处理、缓存亲和、规则隔离 | [并行转移](parallel-transitions.md) |

## 共同方法论

先区分“少做工作”和“同样的工作做得更便宜”。减少节点或模拟次数必须说明省掉的部分为何不影响答案；减少复制或并行等待则需要保持原有语义。两者都应由完整求解的收敛时间验收，微基准、缓存命中数或 CPU 利用率只能帮助解释原因。

等价判断不能只看眼前 HP；状态、后续规则可观察值和概率都属于证明对象。规则审计与回退不是附带功能，而是受限优化正确性的组成部分。以下例子明确区分方法演示与真实测量，不将算例当作新的 benchmark。

这些方法服务于[完整单打、双打的项目方向](../architecture.md#项目方向与优化原则)。矩阵、概率和依赖图方法不要求固定行动数；模拟器捷径仍受各自守卫限制。当前自动行动生成的 1v1 边界并未因此解除。
