# VGC `<= 3v3` 残局可扩展性优化记录（Iter 3：守住链精确收缩、见证条件单调性与大矩阵惰性叶入表）

- 日期：2026-11-21
- 代码基线：`5ac69fb` + [Iter 2 优化](vgc-endgame-scalability-iter2-2026-11-21.md)（Node.js `v24.22.3`，`@pkmn/sim@0.11.0`，`@pkmn/mods@0.11.0`，2 vCPU Linux VM）
- 目标：在不引入神经网络或启发式价值估算、严格维持 `[L, U]` 安全区间、完整动作维度与 `@pkmn/sim@0.11.0` 精确规则等价的前提下，将三类人类牌手对 VGC 残局的直观判断翻译为可数学证明的精确剪枝机制，并对照评估 Iter 2 → Iter 3 在 `rem = 2`（3s / 30s）、`rem = 3`（3s）与 1v1 最难 6 项上的真实收益与剩余边界。

## 诊断证据

对照 [Iter 2 记录](vgc-endgame-scalability-iter2-2026-11-21.md) 中 11 个 3s 未收敛局（及 30s 测量）暴露的三个核心瓶颈：

1. **守住／挺住连点深链（`protectStreak = 1..6`）**：在 `2700945124`、`2700441321`、`2698386833`、`2701260993`、`2702195166`、`2700388082` 等残局中，劣势方单槽或双槽连点 `Protect`（1/3、1/9、1/27、1/81、1/243、1/729）迫使搜索沿几乎完全相同的状态展开 5–6 层子博弈，才能证明连点守住无法逆转。
2. **有替补与吸血招式导致单调盒退化为无角点不透明盒**：`createMonotoneAnalyzer` 在 `aliveBench > 0`（如 `2698386833`、`2701260993`、`2700995275`、`2701004931`、`2699182484`）或对手持有 `Leech Life` / `Bitter Blade` / `Drain Punch` 等吸血招式（如 `2700388082`、`2700995275`、`2700392806`）时，必须保守放弃整条 HP 轴的单调角点，引发大量 `boxSplits` 与重复子博弈求解。
3. **大矩阵急切叶节点入表触发 100k `maxNodes` 天花板与单调/PP 分组污染**：在 30s 预算下，`2700945124`、`2702195166`、`2700441321`、`2698386833` 全部撞上默认 `maxNodes = 100,000` 上限，其中 90%+ 节点从未被初始化，同时将未求解的 `[-1, +1]` 叶节点塞满 `MAX_PP_GROUP_NODES = 128` 与 `MAX_ND_GROUP_NODES = 256` 上限，挤出真正已求解的支配节点。

## 实施的通用优化与正确性边界

### 1. `Protect` / `Endure` 有限视界精确收缩（单槽 `[k]` 与双守住等连击 `[k, k]`）（`src/bounded-solver.ts`, `src/engine/adapter.ts`）
- **数学原理**：在非根节点处，若仅同一方有 1 只或 2 只存活在场精灵处于相同守住连击 `protectStreak = k`（`1 <= k <= 5`），且无任何倒计时场/边状态（天气、场地、戏法空间、顺风、双墙、极光幕、祈愿、预知未来等）、所有存活在场精灵均 `activeTurns > 0`（排除首回合 `Fake Out` / `First Impression`）、无异常状态/混乱/着迷/再来一次锁招、无存活 `Revival Blessing` 及拖延方存活 `Encore`，且对手存在一个合规动作（非换人、非 Mega、非守住/挺住/再来一次、遇 `Spiky Shield` 等接触惩罚守住时排除接触可守住技）在全部非拖延行与拖延失败分支上均证明严格更紧的界，而纯自转移拖延行在成功分支上精确满足 `baseKey(s_{k+1}) === baseKey(s_k)`（或双守住 `s_{k,k} -> s_{k+1,k+1}`），则在 PP 余量保证 `k' <= targetK` 内不会触发挣扎的前提下，按精确成功概率 $p_{k'} = 3^{-k'}$ 从 $k' = \text{targetK} - 1$ 倒推回 $k$，一步计算并认证 $s_k$ 的精确上界或下界，并累加保守证明深度 `(targetK - k) + maxProofDepth` 及见证掩码。
- **正确性边界**：
  - 永不对根节点 `this.rootNode` 直接收缩，完整保留根节点矩阵与策略合同；
  - 静态 `canUsePpTemplateCache` 结合动态存活 `Encore` / `Revival Blessing` 检查（而非整局静态禁用），解锁对手侧或已倒下精灵含 `Encore` 的局面（如 `2700392806`、`2699182484`）；
  - 同步修复安全选格中 `1e-10` 数值保守垫片（LP 与收缩附加的 `1e-10`）在 `bound` 平局时压过 `EPSILON (1e-12)` 导致陷入守住子节点的边界问题（大矩阵改用 `boundTieEps = 1e-7`，小矩阵使用 `FRONTIER_TIE_EPSILON = 1e-9`）。

### 2. 见证条件单调性：`survive-self` 与 `no-drain-opp`（`src/types.ts`, `src/bounded-solver.ts`, `src/engine/adapter.ts`）
- **数学原理**：将单调 HP 轴从二元扩展为四态 `AxisMonoMode = 'unconditional' | 'no-drain-opp' | 'survive-self' | 'opaque'`（1v1 路径仍严格保持 `'unconditional' | 'opaque'` 不变）：
  - **`survive-self`**（放行 `aliveBench > 0` 及对手吸血/反伤/队友击杀联动）：只要本精灵通过自身血线/果子/不安全目标检查，则在最小血量角点 $h_{\min}$ 的证明路径中若该精灵**从未濒死**（`(faintMask & reqNoFaintMask) === 0`），该证明路径上所有伤害均未触及 HP 截断且未触发免费换人，因此同样适用于任意更大血量 $h \ge h_{\min}$；
  - **`no-drain-opp`**（零替补且仅因对手吸血招式未通过无条件单调）：若对手侧证明路径（如最大血量角点 $h_{\max}$ 的上界证伪）**从未在最优支持中使用吸血招式**（`usedDrain === false`），则对手吸血量依赖目标剩余 HP 的非单调性从未触发，该界对整盒有效。
- **原子见证传播与违规直剥**：在 `Action.hasDrain`、`Outcome.faintMask`、`BoundedCell`、`SearchNode`、`MonotoneFrontier2D`、`MonotoneFrontierND` 以及 `_propagatePp` / `_propagateMonotone` / `_tryProtectContraction` 中以原子元组 `(bound, depth, faintMask, usedDrain)` 严格传播；当盒角点违背条件时，`_cellBounds` 将该角点退化为保守端（`-1` 或 `+1`），`_splitOutcome` 向 `outcome.split(violatedSide)` 传递违规方向，直接剥离违规条件轴并对剩余子盒降级标记（`noLowerCond` / `noUpperCond`），避免反复二分死循环。
- **平界混合误切修复**：在大矩阵上当对侧界仍为平界（`flatUpper` 或 `flatLower`）时，将 `_selectionPolicyForRoot` 与 `_selectFrontier` 的混合改进判定阈值设为 `Math.max(1e-3, tolerance * 0.5)`，防止局部已算清次优行与未算清最优行拼出微小混合提升而过早放弃纯策略证明（解决 `2700392806` 的全矩阵展开退化）。

### 3. 大矩阵惰性叶入表与只读查询（`src/bounded-solver.ts`）
- **机制**：仅当根节点为大矩阵（`m_root * n_root > 25`，完全不改变 1v1 路径）时，`_internOutcome` 对未命中 `this.nodes` 的非终局延续结果与盒角点不再立即分配 `SearchNode` 或注册进 `monotoneGroups` / `ppGroups`，而是以只读 `_queryLazySnapshot(snapshot)` 一次性获取当前已有的单调前沿与 PP 同伴界并暂存 `lazySnapshot` / `lazyLowerSnapshot` / `lazyUpperSnapshot`。
- **按需物化与批量收获**：`_selectCellChild` 扫描时对惰性项做 $O(1)$ `this.nodes.get(key)` 挂载；仅当某个惰性叶或惰性盒角点实际胜出成为下探目标时，才再执行一次 `_queryLazySnapshot`——若已有新解收紧该界，则顺带刷新同格其余惰性兄弟并返回 `refreshOnly: true`（零节点分配完成整格收敛）；否则才真正调用 `_intern` 物化。`canExpandCell`、`_tryProtectContraction`、`_findAnyFrontier` 与 `computeExactCertified` 均严格感知惰性项并遵守 `maxNodes` 停止语义，未物化项绝不标记 `exactCertified`。

## 已知取舍与尚未解决的边界

1. **惰性叶“按访问拉取” vs “求解时推送”权衡**：大矩阵惰性叶入表彻底消除了 100k `maxNodes` 撞墙（节点压缩 `5×–23×`）并在 `2698386833`、`rem = 3` 上带来显著突破，但由于未物化兄弟叶节点尚未挂入 `existing.parents` 与单调/PP 分组的推送列表，在高度跨格共享的紧密混合局（`2700441321` 与 `2700945124` 的 30s 下界）上，跨格界收紧从“即时推送”变为“再访拉取”，存在局部延后。后续若需兼得两者，可考虑对“已求解的 `SearchNode`”建立轻量级单向通知或定期扫描根层活跃格的惰性兄弟。
2. **纯精确证书框架在 `3v2` / `3v3` 与深多回合 `2v2` 的结构性边界**：即便叠加动作等价折叠、守住链收缩、条件单调盒与惰性叶入表，单核纯精确/有界搜索在 30s 内对 `rem = 2` 仍停留在 `10/20`（`3v2` 0/2、`3v3` 0/1、`2v3` 0/2）。根本原因在于每层 `80×100` 至 `142×64` 矩阵中要**数学证明**动作 $a^*$ 的下界，仍必须逐一验证所有非等价对手动作（缺乏跨动作支配证明或近似抽象）；这一实验结果为后续是否引入跨动作支配剪枝、策略抽象或评估器提供了清晰的数据分界线。
