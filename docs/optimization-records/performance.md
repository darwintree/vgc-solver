# 5 PP 突袭局面性能记录

日期：2026-09-06。运行环境：Node.js v24.20.0，`@pkmn/sim@0.10.11`。

本文保留前两轮历史测量。后续通用优化及全量测试已完成，当前数据见 [通用优化记录](general-performance.md)。

## 第一轮基准

双方均为 1 HP，突袭、拍落、守住、撞击均为 5 PP。
每次在独立 Node.js 进程内创建对局和新求解器，只计 `solve(battle)` 耗时。
优化前后交替运行三次，测量期间不并行运行其他求解任务，计时不启用 CPU profiler。

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 第一次 | 6,141.87 ms | 3,053.27 ms |
| 第二次 | 6,167.20 ms | 2,984.96 ms |
| 第三次 | 6,183.28 ms | 3,203.26 ms |
| 中位数 | 6,167.20 ms | 3,053.27 ms |
| 已求解非终局状态 | 85 | 85 |
| 模拟器重放次数 | 7,384 | 7,384 |
| 转移调用次数 | 256 | 256 |

中位数加速约 2.02 倍，耗时减少约 50.5%。这是一组局面的本机结果，不代表其他局面具有相同加速比。

复现当前版本：

```bash
npm run benchmark -- --pp 5
```

该命令只计算突袭局面，不运行 Demo 中的剩饭／守住局面。

## 第一轮改动与原因

优化前的独立 CPU 采样中，JSON 深拷贝约占 23%，状态键字符串生成约占 15%，
Showdown 序列化本身也占用明显时间。矩阵求解没有出现在主要热点中。

1. 生成状态键时只替换顶层历史字段，不再深拷贝整个快照。
   创建快照仍会深拷贝，恢复对局也仍会复制输入，确保模拟器不会修改已缓存快照。
2. 回合结束后，终局分支直接保存效用和概率，按胜／负／平合并。
   不再为终局生成完整快照、计算状态键、恢复对局或加入递归缓存。
   未结束的分支仍保留完整快照，按完整状态键合并并继续求解。

`enumerateTurn` 的内部结果现在为 `{snapshot, probability}` 或 `{utility, probability}`。
它的调用方 `OneVsOneSolver` 已同步更新，对外求解结果结构不变。
终局不再进入缓存，因此 `memoHits` 从 198 降至 44；这不代表重复搜索增加。

## 正确性验证

优化前后分别保留所有非终局缓存项，并逐状态比较键、价值、双方策略和收益矩阵。
三轮比较中的 85 个状态全部一致；比较时统一了 JSON 无法保留的 `-0`／`0` 表示。

根节点收益矩阵为 `[[3/5, 1], [1, -1]]`，价值为 `2/3`。
双方根节点策略均为 `5/6, 1/6`，P1 获胜概率为 `5/6`。

回归测试包含 5 PP 和 2 PP 完整求解、先制必胜局面、矩阵算法，
并补充了终局概率合并、连续守住下终局／非终局混合分支、状态键稳定性和快照隔离测试。
上述针对性测试已通过。全量 `npm test` 的剩饭／守住搜索长时间未结束，已手动停止；
本次没有确认全量测试通过。

## 第二轮基准

沿用同一 5 PP 局面和独立进程计时方法，三轮交替比较第一轮版本与第二轮版本：

| 测量 | 第一轮版本 | 第二轮版本 |
| --- | --- | --- |
| 第一次 | 3,106.55 ms | 2,440.26 ms |
| 第二次 | 3,054.65 ms | 2,427.05 ms |
| 第三次 | 3,063.60 ms | 2,542.39 ms |
| 中位数 | 3,063.60 ms | 2,440.26 ms |

本轮耗时再减少约 20.3%，加速约 1.26 倍；相对最初记录的 6,167.20 ms，累计约快 2.53 倍。
85 个非终局缓存项的状态键、价值、策略和收益矩阵均通过三轮逐项差分比较。
模拟器重放次数仍为 7,384，转移调用次数仍为 256，memoHits 仍为 44。

第二轮改动：

1. `@pkmn/sim@0.10.11` 的反序列化已经递归重建绝大部分可变数据。
   `restoreBattle` 仅提前复制它直接保留引用的日志数组和 Pokemon.set，避免全快照重复深拷贝。
   仍由 `Battle.fromJSON` 重建 Battle／Side／Pokemon 等内部引用关系。
   这依赖固定版本的实现，升级模拟器时需重新核对保留引用的字段。
2. 重放已有随机决定时，直接校验并返回决定；只有遇到新随机调用才构造候选结果和精确概率表。
   随机分叉、概率算法和游标语义不变。

新增测试覆盖冻结快照、嵌套状态和引用关系隔离、随机概率与决定重放、克隆游标和重放分歧检测。
本轮使用以下命令运行回归，排除了前一轮长时间未结束的剩饭／守住完整搜索：

```bash
node --test --test-skip-pattern='symmetric Leftovers/Protect'
```

另对剩饭／守住局面的四种首回合行动组合比较了优化前后的完整转移分布。
这些检查不等同于完成该局面的全局求解回归。

## 剩余成本

本次没有减少随机分支数，也没有引入采样、招式专用公式或近似状态合并。
优化后的主要成本仍是模拟器事件处理以及每次重放时恢复对局。
继续加速需要进一步减少或降低重放成本，并证明状态恢复和随机分支语义不变。
