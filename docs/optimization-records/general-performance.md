# 通用优化探索与验收

日期：2026-09-06。Node.js v24.20.0，`@pkmn/sim@0.10.11`。
主代理规划与独立验证；三个 `gpt-5.6-luna`、high 推理子代理在隔离副本中实现。
基线是本轮开始时的工作区，已经包含前两轮优化；此次突袭基准采用每招 5 PP。
后续默认局面已按用户要求切换为各招式满 PP，复现这里的 5 PP 数据需显式传入 `--pp 5`。

5 PP 和先制必胜用例按旧版／新版交替测量；其它新版局面各测三次。

## 采纳的优化与证明条件

1. **随机树只重放完成路径。** 未知随机调用在当前 Battle 中选择一个候选继续，
   其它候选保存概率和决定前缀后入栈。仍遍历有限分布，不进行采样或概率阈值截断。
2. **整批空事件消除。** 仅在所有 active 都没有 handler 时跳过排序和分发。
   任何目标有 handler 就保留原生整批处理，避免遗漏前一个回调为后一个目标新增 handler 的情况。
   空 Weather 仍执行原生要求的 Update 递归；深度上限和方法覆盖会触发原生回退。
3. **副作用整数桶合并。** 原生代码只观察 `random(100) < chance` 的结果。
   使用相同 32 位桶质量的真假分支，小数阈值保留向上取整的整数桶语义。
   直接使用 PRNG，避免错误服从原来不适用的 `forceRandomChance`。
4. **伤害映射合并。** 在原生、无副作用的截断函数下，16 个 roll 若返回相同整数伤害，
   合并其概率；其它伤害修正、状态、道具和事件仍由模拟器执行。
   不依据对手剩余 HP 直接推断击倒，不删除伤害历史字段。
5. **价值证书剪枝。** 子状态的整行所有随机结果严格为 +1，或完整行与完整列构成纯鞍点时，
   可确定价值而不求其它单元。根结果仍完整；以后将 value-only 缓存项作为根求解时会补全。
6. **矩阵 simplex。** 正移位与归一化后求解，从最终基重新计算 primal 与 dual，
   验证双方策略在原矩阵上的收益保证。失败时最多对 6×6 矩阵使用枚举回退；
   更大矩阵的数值失败显式报错。simplex 没有多项式最坏复杂度保证。

这些优化没有写死突袭、守住、宝可梦种族、1 HP 或 PP 数量。
模拟器方法优化仅安装到枚举器恢复的实例，不改变全局 prototype，也不改变用户初始对局的固定种子运行过程。
空事件优化限已审计的第九世代原生方法；副作用和伤害方法同样检查原生方法身份，
伤害映射要求原生 `Math.trunc`。依赖升级需重新审计，方法身份检查不是跨版本正确性的证明。

## 独立验证

- 主代理保存旧版输入快照及完整后继状态分布，比较命中／伤害、副作用、同速固定伤害、
  连续守住、换人、显式双打目标六类转移；所有状态键与概率一致，概率比较容差 `1e-12`。
- 其中命中／伤害用例从 3,237 次模拟降到 43 次；副作用用例从 3,875 次降到 51 次。
  这两个用例的原始小整数副作用掷骰分别产生大量等价路径。
- 5 PP 的 41 个、8 PP 的 101 个访问状态均存在于旧版缓存中，逐状态价值以及根矩阵通过差分。
  LP 引入约 `1e-15` 级舍入差异。退化矩阵的均衡不唯一，因此不要求返回相同的任意纯策略。
- 主代理生成 100 个递归随机状态图，比较优化与完整递归版本的根矩阵和每个访问状态价值。
- 主代理独立检查 625 个离散 2×2 矩阵，以及 500 个近重复行矩阵及各自的 `1e-12`、`1e12` 缩放。
  矩阵候选曾两次失败，修复最终基恢复及数值回退后通过。
- 永久测试保留原始异常重放 oracle，验证小数副作用概率、强制概率开关、自降能力、
  两次均实际执行的 Double Kick，以及显式换人／双打转移。
- `npm test` 全量通过，包含此前未完成的剩饭用例；最终一次约 10.73 秒。
  测试耗时的大部分来自故意保留的慢速原生分布对照。

矩阵出口证书的容差按最大收益幅度缩放（约 `1e-8 × scale`）；
这仍是双精度数值求解，不是有理数符号证明。剪枝不额外使用“接近相等”的宽松判断。

## 未采纳方案及停止条件

选择性复制快照仅复制 `Pokemon.set` 的候选，在单独快照微基准中更快，
但子代理三次完整求解测量没有稳定收益。保留现有完整快照隔离语义，本轮不合并该候选。
有缺陷的提前丢弃候选列方案也没有采纳；最终惰性矩阵通过每格缓存补齐所有必要单元。

最终 CPU 采样仍以模拟器事件查询、对象构造和恢复为主；JSON 复制与状态键只占较小部分。
继续修改日志、事件顺序、状态字段或模拟器内部对象布局，需要新的可观察性和等价性证明。
当前三个完整用例已完成，已找到且有稳定收益的通用候选均已验收；暂未找到值得继续落地的安全改动。

这不代表任意 6 选 3 首回合已经可快速精确求解。当前自动行动生成只覆盖单只 active 的招式选择，
未实现完整选队、换人、双打联合动作或信息不完整时的信念状态。
连续 `random()` 仍不支持；真正循环需要不动点求解；状态上限目前按已完成状态统计，
深递归仍可能先受到调用栈或内存限制。未来更大局面还需要独立评估搜索规模与求解模型。
