# VGC `<= 3v3` 残局可扩展性优化记录（Iter 2：动作等价折叠、单遍状态键、多精灵单调支配与大矩阵证伪调度）

- 日期：2026-11-21
- 代码基线：`5ac69fb`（Node.js `v24.22.3`，`@pkmn/sim@0.11.0`，`@pkmn/mods@0.11.0`，2 vCPU Linux VM）
- 目标：在保持 1v1 历史 54 集无退化（`10s, tol = 0.02`）、严格 `[L, U]` 安全区间、完整动作维度与 `@pkmn/sim@0.11.0` 精确分布（`TVD = 0`）的前提下，围绕 VGC `<= 3v3` 实战残局（`rem = 2` 共 20 局与 `rem = 3` 探测 17 局）持续定位剪枝与吞吐瓶颈，评估单核精确/有界搜索在 `<= 3v3` 上的真实边界。

## 诊断证据

对基线 `5ac69fb` 在 20 局 `rem = 2` 残局上的 CPU profile 与根矩阵诊断暴露 6 个通用瓶颈：

1. **大矩阵等价动作重复展开**：双打中大量招式组合因先手击杀未行动槽位、睡眠未行动、`Follow Me` 重定向或目标已倒下而产生完全相同的状态分布，却逐格重复运行 `stepBattle`、单独存储与刷新 `BoundedCell`。
2. **`mergeActiveBranches` / `finalizeOutcomes` 的 5 遍全状态键构建**：`HpDist` 折叠逐精灵重复调用 `canonicalStateKey` 并执行 `.map(e => e.prob.toFixed(9)).join(',')`，合计占 36%–40% inclusive CPU。
3. **多精灵单调性覆盖缺口与 `ppTemplateCache` 限于 1v1**：`monotoneSignature` 仅在剩余 `1v1` 子博弈生效；`Last Respects` 在 Choice 锁招（无替补、无解锁道具机制）后仍过度禁用队友单调性；`Gale Wings` 等血线特性在对手已残血且无治疗时仍过度禁用目标单调性；`ppTemplateCache` 仅在 1v1 开启，且未在非守住回合屏蔽 `protectStreak`。
4. **多轴非单调盒深度 0 盲目碎盒**：`3v2 / 3v3` 与吸血招式下的多轴无角点非单调盒在深度 0 反复二分数百至数千次（如 `2700995275` 达 1,324 次 `boxSplits`），迟迟不下探具体局面。
5. **纯规则双打动作排序与大矩阵调度失衡**：规则排序无法区分实际击杀/伤害与无效消耗（如 `Weather Ball` 晴天 100 威力与 `Heat Wave` 90% 命中）；大矩阵上 `preferUnexpanded` 覆盖已展开证伪格、tied-bound 优先大 `gap`（反证伪顺序）、停滞行/列不轮换、以及根节点 `autoJoint` 穿透纯策略子节点并因 `0.0002` 退化 LP 平局误触发。
6. **急切叶节点入表与 `maxNodes = 100,000`**：在 30 秒预算下 90%–95% 已入表节点从未被初始化，却计入默认 `maxNodes = 100,000` 上限（阻塞 `2700441321`、`2700945124`、`2698386833`、`2702195166`）。

## 实施的通用优化与正确性边界

### 1. 观测驱动的动作等价折叠与共享 `BoundedCell`（`src/engine/types.ts`, `src/engine/turn.ts`, `src/engine/adapter.ts`, `src/bounded-solver.ts`）
- 在 `stepBattle` / `runActionLoop` / `executeMoveAction` / `resolveTargets` 中记录每槽位最小观测位掩码（`ACTION_OBS_EXECUTED`、`ACTION_OBS_CATEGORY`、`ACTION_OBS_EXACT`、`ACTION_OBS_SLEEP_ONLY`、`ACTION_OBS_OPP_TARGET_MATTERED`）与初始 `(priority, subOrder)`，仅在 `complete === true` 且无全局异常观测机制（如 `Quick Draw` / 换人暂停）时产出 `actionObs`。
- 在 `computeEquivalentSideIndices` 中严格按两类规则产出 `equivalentRows` / `equivalentCols`：
  - 未行动/睡眠未醒槽位：仅在同 `(priority, subOrder)`、非特殊预声明技（`Focus Punch`/`Beak Blast`/`Grassy Glide`）、睡眠未醒非 `Snore`/`Sleep Talk`、且若 `ACTION_OBS_CATEGORY` 置位（如 `Sucker Punch`）则保持伤害/变化类别一致时折叠；
  - 双打敌方目标槽位：仅当 `ACTION_OBS_OPP_TARGET_MATTERED === 0`（如 `Follow Me` 全量重定向或目标槽位未参与结算）且招式/Mega 相同、均指向敌方槽位时折叠 `+1`/`+2`。
- 在 `BoundedSearch._acceptTransition` 中令等价行列共享同一个 `BoundedCell` 引用并记录 `coords: CellCoord[]` 与 `populatedCellCount`，在 `_refresh`（含大矩阵 `populatedCells` 与小矩阵全扫描双分支）和 `_splitOutcome` 中同步全部等价坐标，保持 `exactCertified` 与区间单调性严格诚实。

### 2. 单遍 `HpDist` 折叠、`HpDist` 不可变共享与通用 `ppTemplateCache`（`src/engine/state.ts`, `src/engine/turn.ts`, `src/engine/adapter.ts`）
- 将 `HpDist` 视为不可变数组（`clonePokemon` 直接复用引用），以 `WeakMap<HpDist, string>` + 整数精度 `Math.round(e.prob * 1e9)` 缓存键串；为 `canonicalStateKey` 增加位掩码参数 `maskHpBits` 与 `maskProtectBits`。
- 重写 `mergeActiveBranches` 与 `finalizeOutcomes`：每个分支仅调用一次 `canonicalStateKey(..., activeMaskBits)` 构造 `baseKey` 与 `hpKeys`，随后基于 `baseKey + hpKeys` 单遍完成精确去重与逐精灵边缘 HP 折叠（与 `discrete` 模式 `TVD = 0`）。
- 将精确 `ppTemplateCache` 从 1v1 推广到全部 `ppLinearSafe && maxPpLossPerTurn <= 2` 的单双打局面；并在无间接守住调用（如 `Encore`/`Revival Blessing`）且无活替补引发的回合中换人暂停时，对当前回合未点守住/挺住招式的精灵精确屏蔽 `protectStreak`（`protectMaskForTurn`）。

### 3. 多精灵 N 维单调支配、动态招式/血线判定与非单调盒渐进细化（`src/engine/adapter.ts`, `src/bounded-solver.ts`）
- 将 `monotoneSignature` 与 `BoundedSearch._registerMonotone` / `_propagateMonotone` 推广到任意多精灵 N 维带符号 HP 向量（`+hp` 本方、`-hp` 敌方，`kind: 'nd'`，设 `MAX_ND_GROUP_NODES = 256`、`MAX_ND_FRONTIER = 64` 上界，单边 `<= 1` 只单调精灵时仍走原有 1D/2D 快速路径）。
- 在 `createMonotoneAnalyzer` 中增加零替补永久 Choice 锁招与 0 PP 招式过滤（`monAvailableMoveFlags`，遇 `Knock Off`/`Trick`/`Magic Room`/`Imposter` 等物品解锁或 PP 恢复机制 fail-closed），并对对手反伤招式触发血线特性改为动态判定（`monAbilityStillHasThreshold`）。
- 升级多轴非单调 `makeMultiBoxOrSingleton` 分裂（多非单调轴剥离中位具体/有角点点 + 惰性余片；单非单调轴剥离 4 个等距点 + 惰性余片），并在 `BoundedSearch._selectCellChild` 中对大矩阵分离角点盒与无角点不透明盒（`deferOpaqueSplit` 仅在大矩阵 `M×N > 25` 生效，避免干扰 1v1 惰性尾桶）。

### 4. 物理伤害驱动的双打动作排序与大矩阵证伪优先调度（`src/engine/adapter.ts`, `src/bounded-solver.ts`）
- 以 `createDoublesActionScorer` 替换纯规则排序：利用实时能力/天气/场地/属性克制/STAB/常见增伤特性与道具估算双打单双目标击杀率（含 `Weather Ball`、`Terrain Pulse`、`Last Respects`、超场挡先制、`Sucker Punch` 不可靠惩罚、重复过量击杀惩罚与双目标联杀覆盖奖励），完整保留全部合法动作维度。
- 大矩阵（`M×N > 25`）调度改进（1v1 小矩阵路径不变）：
  - 证伪优先选格：在同 `bound` 平局时优先更小 `gap`（先深入已有部分反证的列/行，减少坏行全列扫描），并在行/列平局时按乐观界（更高 `rowOptFloor` / 更低 `colOptCeil`）打破平局；取消大矩阵纯 `security` 下 `preferUnexpanded` 对已展开证伪格的覆盖；
  - 大矩阵 `auto` 策略按节点局部判定（子节点不再被迫继承根节点的 `'joint'` 模式），且混合改进阈值设为 `1e-3`（防止 `0.0002` 退化 LP 平局误锁死搜索）；
  - 结合不对称平界方向（`3:1` 偏向动作更少一侧）、容差感知双最优见证、子节点局部方向自适应、以及随维度缩放的停滞探针轮换（`rowStallProbes`/`colStallProbes`，任意显著进展即清零）。

## 结论：3v3 边界判断与通往 4v4 的结构瓶颈

在单核 + 30 秒 + 严格有界/精确合同下，**`<= 3v3` 不对称残局已基本打通，但完整 `2v2/2v3/3v2/3v3` 尚不能 20/20 全量解决**。剩余 10 局暴露 4 道必须从架构层面突破的结构墙（进入 `4v4` 后会进一步放大）：

1. **`Protect` 连续链与局部循环界**：必败残局反复靠 `PS0 → PS1 → PS2 → PS3` 把上界拖在 `-1/3`、`+1/9`、`+23/81`，需要在不引入循环自证的前提下构造安全的有限步收缩或跨 `PS` 级单调/上界复用。
2. **有后排（`aliveBench > 0`）与吸血招式的 HP 非单调性**：`2v3/3v2/3v3`（以及几乎全部 `4v4`）在双方均带替补时无法启用 HP 单调盒，需要安全的不致死局部区间单调性（例如在保证双方不倒下的严格存活区间上复用单调界）来压缩 `16×16` 伤害乘积。
3. **惰性叶节点与多核并行**：90%–95% 的节点从未被展开却占满 `maxNodes = 100k` 并拖慢组维护；同时 `AsyncBoundedSolver` 目前仍仅对接 Showdown worker，尚未把 `compact` 引擎接入多核并行转移/批量前沿扩展。
4. **深回合心理博弈与动作抽象**：`Protect + Sucker Punch + Swords Dance` 镜像（5–10 回合）及 `4v4` 的 `150×150+` 动作矩阵，仅靠严格精确/有界博弈树已接近信息论与组合复杂度上限；走向 `4v4` 及选人阶段（6选3 / 6选4）需在“精确/有界终局求解器”之外叠加安全的迭代动作/状态抽象或价值函数引导的混合求解架构。
