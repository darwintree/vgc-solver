- 日期：2026-11-21
- 代码基线：`5ac69fb` + [Iter 2 优化](vgc-endgame-scalability-iter2-2026-11-21.md) + [Iter 3 优化](vgc-endgame-scalability-iter3-2026-11-21.md)（Node.js `v24.22.3`，`@pkmn/sim@0.11.0`，`@pkmn/mods@0.11.0`，2 vCPU Linux VM）
- 目标：回应 Iter 3 在扩大求解集合上仍停留在 `rem = 2`（3s `9/20`、30s `10/20`）的问题；在不引入神经网络、启发式估值或缩减满 PP 的前提下，通过严格健全的通用支配传播、守住链泛化、盒角点见证保活与精确 LP 跳过，实质扩大 `rem = 2` 限时收敛集合并整体收紧其余复杂局区间。

## 诊断证据

对照 [Iter 3 记录](vgc-endgame-scalability-iter3-2026-11-21.md) 的剖析结果，发现四个直接阻碍收敛扩张的通用瓶颈：

1. **惰性叶“拉取延迟”与 `(HP × PP)` 正交割裂**：Iter 3 引入的大矩阵惰性叶虽然清除了 100k `maxNodes` 撞墙，但未物化叶无法接收同态或支配状态的即时界更新；同时 `monotoneGroups` 要求精确 PP、`ppGroups` 要求精确 HP，导致不同血量且不同 PP 的同类残局（如 `2700945124` 的 `1v2` 与 `2698386833` 的多回合守住/伤害展开）无法跨 `(HP × PP)` 共享已证下界/上界。
2. **双打守住收缩的五类可安全放宽限制**：
   - `protectContractionInfo` 要求双槽守住连击必须严格相等（`s0 === s1`），导致双打中最常见的 `(Attack, Protect) -> (0, 1) -> (Protect, Protect) -> (1, 2) -> (2, 3)` 非对称双守住链完全无法收缩；
   - 双方相等正顺风（`tw0 === tw1 > 0`）、对当前阵容零影响的惰性场地（`psychic` / `electric` / `misty`）、无 `Fake Out`/`First Impression` 精灵的 `activeTurns === 0` 换入回合、拖延方有安全备用攻击技防止挣扎时的守住低 PP，以及含 `bucketSmallTail` 尾桶的守住格，先前均被一刀切拒收。
3. **盒角点脏见证覆写退化与违规盒饥饿**：在含反伤招式（如 `Brave Bird` / `Flare Blitz`）且带替补的对局中（如 `2698386833` 的 `r[28] o[0]`，`p = 0.4951`），`upperChild` 先证出干净界（`-0.9722`, `uF = 3` 满足 `uReq = 192`），随后又细化出仅紧 `0.0018` 但队友反伤濒死的脏见证（`-0.9740`, `uF = 131`），导致 `_cellBounds` 丢弃已证干净界并将整盒退回 `+1.00`；更糟的是 `_selectCellChild` 中的 `deferOpaqueSplit` 会因 `0.3%` 未展开尾分支而推迟分裂该违规盒，锁死整格上界。
4. **大矩阵无效矩阵重解与已证列过早轮换**：在 `64×80` / `80×116` 大矩阵中，单调格更新未命中对侧平衡支持时仍在重复调用 `solveMatrixFast`；且在已证出紧上界的列上，`colStallStep = max(64, 2*m)` 不足以解完一个大型 `2v3` 子节点，导致搜索中途放弃最优列并轮询无关 `+1.0` 列。

## 实施的通用优化与正确性边界

### 1. 联合 `(条件 HP × 有限视界 PP)` 支配与零节点推送监视器（`src/bounded-solver.ts`, `src/engine/adapter.ts`）
- **联合签名与单调传递**：`jointMonoPpSignature` 同时屏蔽全部 PP 与非不透明（`unconditional` / `no-drain-opp` / `survive-self`）HP 轴，并用 `turn0Mask` 隔离 `Fake Out` / `First Impression` 首回合状态，条件轴静态排除 `Endure` 持有者。`JointMonoPpGroup` 维护帕累托前沿见证 `lowerWitnesses` / `upperWitnesses`，经 `jointTransferLowerMask` / `jointTransferUpperMask` 严格校验 HP 方向、条件见证掩码（`survive-self` 禁止降对手血且要求己方无濒死、`no-drain-opp` 要求无吸血）、及有限视界 PP 兼容阈值 `maxPpLossPerTurn * depth` 后才跨 `(HP × PP)` 传递，并保守置位降低对手 HP 后的传递 `faintMask` 以保证传递闭包健全。
- **零节点推送监视器**：对未物化的惰性叶与惰性盒角点，在不分配 `SearchNode` 的前提下注册轻量 `lazyExactWatchers`（精确同态键）与 `JointMonoPpGroup.lazyWatchers`（联合支配组），并按角点所需 `(reqNoFaintMask, reqNoDrain)` 过滤查询与推送，避免脏见证遮蔽干净见证；受推父节点记入 `deferredDirty` 并在回溯循环中增量刷新。

### 2. 精确守住链收缩六项泛化（`src/types.ts`, `src/engine/state.ts`, `src/engine/adapter.ts`, `src/bounded-solver.ts`）
- **非对称双守住 `(s0, s1)`**：放行 `1 <= s0, s1 <= 6` 且 `min(s0, s1) < 6`，新增 `stallActionMask`（区分单槽 0、单槽 1、双槽守住）与 `inspectOutcome.succMask`，按每槽精确成功概率 $p_{r,t} = 1 / \min(729, 3^{\min(6, s_r + t)})$ 分别对单槽 0、单槽 1、双槽自转移与混合行做精确向后归纳。
- **双方相等正顺风（`tw0 === tw1 > 0`）**：在 `canonicalStateKey` 中新增 `maskEqualTailwind`，严格限制双方无人可触发 13-bit 速度回绕（基础速度 `<= 340`）、无 `Gyro Ball`/`Electro Ball`/非负号 `Trick Room`、拖延方无顺风/间接调招，且见证校验对手证明路径未使用 `Tailwind`（`TW_P1_BIT` / `TW_P2_BIT`）。
- **精确惰性场地（`isTerrainInert`）**：对 `psychic` / `electric` / `misty` 场地逐一审计在场与替补全部精灵的招式、特性、道具与状态（如超场禁止超能攻击技、对敌先制技、满血疾风之翼、场地种子等），仅当场地对剩余对局全过程严格无任何效果时放行并屏蔽场地计时。
- **其余三项精确放宽**：`activeTurns <= 0` 仅在携带 `Fake Out` / `First Impression` 时禁用收缩；在 `!battleHasMoveLocker` 且拖延精灵拥有足量 PP 的安全非变化备用攻击技（不会触及挣扎）时，允许拖延方守住/挺住 PP 低于视界；`_tryProtectContraction` 支持含 `o.split && refSnap === null` 尾桶的守住格，将缺失失败质量保守计作 `DEFAULT_UPPER` / `DEFAULT_LOWER`。

### 3. 单调干净盒见证缓存与违规盒防饥饿（`src/bounded-solver.ts`）
- 在 `BoundedOutcome` 上增加单调缓存 `validBoxLower*` / `validBoxUpper*`（含对应认证深度与见证掩码）：凡盒角点一旦在满足 `(reqNoFaintMask, reqNoDrain)` 的前提下证出有效界，即永久保留其最优干净界，后续角点因更紧但违背条件的见证刷新时绝不将盒界退回 `±1.0`；在惰性角点挂载已有 `SearchNode` 前亦先保存有效惰性界。
- `_selectCellChild` 中对已发生条件违背的盒（`bestOpaqueIsViolated` 或目标方向角点违背）禁止被 `deferOpaqueSplit` 推迟在极小未展开尾分支之后，立即触发精确分裂。

### 4. 精确互补松弛 LP 跳过与大矩阵调度改进（`src/bounded-solver.ts`）
- **互补松弛 LP 跳过**：在 `_refresh` 中利用单调性（$L' \ge L$、$U' \le U$）与零和鞍点互补松弛定理：当 `lowerMatrix` 的全部变更格均不命中 `prevLoP2[j] > 0`（或 `upperMatrix` 变更格均不命中 `prevHiP1[i] > 0`）时，原平衡解仍为严格全局最优鞍点，直接跳过 `solveMatrixFast`。
- **O(m + n) 鞍点快路径与大矩阵工作量归一化**：`_refresh` 将增量 `rowFloor`/`colOptCeil` 与 `rowOptFloor`/`colCeil` 传入 `solveMatrixFast`；`_selectCellChild` 对大矩阵候选分支按 `Math.sqrt(estB)` 做工作量归一化（不改动用于渐进游标判定的无权 `maxSingleScore`）；已证紧界行/列的轮换阈值按矩阵边长缩放为 `Math.max(64, 8 * n)` / `Math.max(64, 8 * m)`（未证 `±1` 行/列保持 `Math.max(64, 2 * n)` / `Math.max(64, 2 * m)` 快速轮换）。
